# UI / UX tooling research (2026-10-20)

Question: which tools could improve MetaLens VGC's motion and design (motion.dev, anime.js, Bklit UI, Kokonut UI, Manus, and
anything else), and how do they fit a site that is plain ES modules with no framework, no bundler, no new runtime deps,
nothing from CDNs, and an owner-set motion budget ("not overwhelming": opacity/transform only, one signal per action,
nothing moves on scroll, all off under reduced motion; the e2e "motion" check enforces an allowlist)?

## Verdicts

| Tool | What it is | Fits here? | What we took |
|---|---|---|---|
| [motion.dev](https://motion.dev) (vanilla `motion`) | `animate()`, `scroll()`, `inView()`; `motion/mini` (~2.6 kB) is a thin layer over the Web Animations API (WAAPI), the full build (~18 kB) adds springs, sequences and independent transforms | Technically yes (vanilla, could be vendored from npm like ECharts) | **Not vendored.** The mini build is WAAPI, which we can call directly; its standout feature, springs, is reproduced with a CSS `linear()` curve (`--ease-spring` in app.css, damped spring, zeta 0.6). |
| [anime.js v4](https://animejs.com) | Modular ESM: timelines, `stagger`, SVG line drawing, draggable, text splitting | Technically yes | **Skipped.** Its strengths (choreographed timelines, staggers) are exactly what the motion budget rules out. Revisit only for a one-off showpiece (e.g. a Credits SVG line draw). |
| [Bklit UI](https://github.com/bklit/bklit-ui) | React + visx + Motion chart components via the shadcn registry (area, bar, ring, gauge, radar, sankey, live line...) | **No**: React/Tailwind source components | Patterns ported to ECharts: series focus on hover (other lines dim), dashed crosshair on axis tooltips, tooltips sorted by value. |
| [Kokonut UI](https://kokonutui.com) | React + Tailwind + Motion component set (bento grid, hold button, particle button, beams background, AI prompt box) | **No**: React; visually louder than the budget allows | Press feedback on standalone buttons (scale .96 Pro, 1px press Retro). The bento grid idea is already how the 12-column grid works. |
| [Manus](https://manus.im) | An AI agent that builds websites and apps from a prompt (now part of Meta) | **Not applicable**: not a UI library | Nothing. Agent-generated sites would not respect the data rules (real data only, source + n + date on every view). |

## The better fit: what the platform already does (no dependency)

| Feature | Support (2026) | Use here |
|---|---|---|
| CSS `linear()` easing | All current engines | Springs without JS (`--ease-spring`, chip pop). Guarded with `@supports` so older engines keep `ease`. |
| Same-document View Transitions | Chromium 111+, Safari 18+, Firefox 144+ | Already used for the skin/theme cross-fade (`crossfade()` in ui/motion.js). |
| Scroll-driven animations | Chromium, Safari 26; Firefox status unclear | Already used for the scroll hairline under the sticky bar (`@supports` guarded). |
| `@starting-style` | Chromium 117+, Safari 17.5+, Firefox 129+ | Candidate for popover / dialog entry. **Not used**: settings.css says "no animation (motion budget)". |
| Popover API, `<dialog>` | All | Already used (settings gear, clock, What's new). |
| CSS anchor positioning | Chromium; others partial | Could replace the JS clamp in ui/tip.js later. Not worth it until Firefox ships it. |
| `content-visibility` / `contain-intrinsic-size` | All | Candidate for below-the-fold cards. The main.js IntersectionObserver already defers their render. |

## Shipped in v1.5.0
1. **Layout shift on load** (the open QA finding): grid rows size by content, and the first screen reserves about its filled
   height. Measured CLS: desktop 0.263 -> 0.022, phone 0.381 -> 0.056 (Playwright `PerformanceObserver('layout-shift')`).
2. **Sticky chrome** at >=1280px: Copy link + Hide end the first filter row instead of wrapping onto a row of their own (38px less).
3. **Leaderboard headers**: real buttons with `aria-sort`, focus kept after a re-sort; the sprite column has a screen-reader name.
4. **Spring pop** on new chips, **press feedback** on buttons, **trend charts**: series focus, value-sorted tooltips, dashed crosshair.

## Considered and left out (with reasons)
- **Shared-element morph** (row sprite flies into the drawer hero via `view-transition-name`): the drawer already slides in,
  and a document view transition also cross-fades the whole page. That makes two signals for one action. Revisit if the
  owner wants it in place of the slide.
- **Count-up numbers, scroll reveals, hover lift**: removed on purpose on 2026-09-30 (motion budget). Not re-added.
- **Gradient area fills under trend lines**: eight overlapping fills turn into mud. Fine for a single-series sparkline if one is added.
- **Popover fade-in** via `@starting-style`: explicitly ruled out by settings.css ("no animation").

## Ideas for later (ranked)
1. Mobile main-thread cost: decoding ~9 MB of data blocks first paint on phones (Lighthouse mobile perf < 10). Move
   `decode()` to a Web Worker (the libs are pure ESM, so a module worker can import them as they are).
2. A KPI ring/gauge (Bklit "ring") for the snapshot's top-12 share, drawn with ECharts gauge. It needs the owner's call on the snapshot layout.
3. `content-visibility: auto` on below-fold sections, measured against the existing IntersectionObserver deferral.
4. Anchor-positioned `[data-tip]` tips once Firefox ships anchor positioning, dropping the JS clamp.
